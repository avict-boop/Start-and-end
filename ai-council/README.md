# Совет нейросетей (AI Council)

Несколько моделей (Claude, ChatGPT, Gemini, Kimi, DeepSeek и др.) решают одну задачу, как совет экспертов:
предлагают варианты вслепую, анонимно критикуют чужие, дорабатывают свои, голосуют, а председатель
выносит итоговое решение с обоснованием и особыми мнениями. Все модели подключаются через
[OpenRouter](https://openrouter.ai), поэтому нужен **один ключ**.

## Как проходит заседание

```
[0] Постановка   председатель уточняет вопрос и задаёт 3–5 критериев (или ваши: --criteria)
[1] Предложения  участники параллельно и вслепую предлагают свой вариант (председатель — нет)
[2] Анонимизация варианты перемешиваются и получают метки A, B, C…
[3] Критика      каждый оценивает чужие варианты по критериям (шкала 1–10 с описанием уровней)
[4] Доработка    каждый видит критику своего варианта и улучшает его      ← [3–4] × N раундов
[5] Голосование  ранжирование чужих вариантов: порядок по методу Шульце (прямые сравнения),
                 при равенстве — Борда, попарный счёт, жребий; мера согласия совета (τ Кендалла)
[6] Вердикт      председатель: победитель, финальный ответ, почему, особые мнения, риски
```

Защита от типичных проблем:
- **Самопредпочтение.** Варианты анонимны, за свой вариант голосовать и оценивать его нельзя.
- **Председатель не судит сам себя.** По умолчанию у него нет своего варианта: он ставит задачу, оценивает,
  голосует и пишет итог (`chair_proposes: false`; вернуть прежнюю схему — `true`, галочка в вебе или `--chair-proposes`).
- **Формат ответа.** Все модели видят исходный запрос дословно и обязаны соблюдать заданную в нём структуру
  (разделы, таблицы) — председатель тоже.
- **Подсчёт.** Порядок определяет метод Шульце: кто выигрывает в прямых сравнениях (устойчив к похожим
  вариантам и к «утоплению» соперника). При равенстве — балл Борда, попарный счёт, жребий. Оценка критики
  показывается для сведения: она дана версиям до доработки.
- **Председатель следует голосованию** (`chair_follows_vote: true`): другой победитель — только при опровергнутых
  фактах, серьёзном риске или если лидер не отвечает на вопрос; отступление выделяется в отчёте.
- **Экономия.** «Компактные варианты» (галочка в форме, «📝 Компактно» в Telegram, `--compact`, по умолчанию —
  в настройках): участники пишут суть сжато, полный ответ в нужном формате пишет только председатель — примерно
  в 2–3 раза дешевле. Общее начало запросов (вложения и вопрос) кэшируется у провайдеров — повторное чтение
  стоит дешевле; сколько прочитано из кэша, видно в отчёте.
- **Стратегическое голосование.** Бюллетени, идущие против мнения остальных (например, лидер на последнем месте),
  помечаются, а подсчёт повторяется без них: видно, устойчив ли победитель.
- **Факты.** По желанию (`fact_check.enabled`, галочка в вебе, кнопка в Telegram, `--fact-check`) модель с поиском
  в интернете (Perplexity) проверяет ключевые утверждения двух лидеров голосования; председатель учитывает итог.
- **Председатель под контролем.** В статистике видно, как часто председатель выбирает не лидера голосования.
- **Надёжность решения.** Показывается согласие совета — насколько одинаково модели упорядочили варианты
  (высокое / среднее / низкое); при низком над решением выводится предупреждение.
- **Конформизм.** Первый раунд проходит вслепую, а один участник может быть «адвокатом дьявола».
- **Сбои провайдеров.** Упавший участник выбывает из этапа, заседание идёт дальше, пока есть кворум.
  Если не ответил председатель, итог подводится по голосованию.
- **Кривой JSON.** Ответы проверяются по схеме (pydantic). При ошибке модель получает подсказку и отвечает повторно.
- **Расходы.** Перед стартом программа проверяет, что все модели есть на OpenRouter (и подсказывает похожие id),
  и показывает план вызовов с оценкой стоимости по актуальным ценам. Во время заседания действует жёсткий лимит
  `max_cost_usd`, учитывается фактическая стоимость, которую возвращает OpenRouter.

### Режимы

| Режим | Что происходит | Когда использовать |
|---|---|---|
| `quick` | предложения → голосование → вердикт | быстро и дёшево |
| `debate` (по умолчанию) | + критика и доработка, `--rounds N` | важные решения |
| `evaluate` | вы даёте готовые варианты, совет их оценивает и выбирает | выбор из известных вариантов |
| `research` | подвопросы и углы зрения → слепые варианты → критика → **поиск проверяет утверждения всех вариантов** → доработка по источникам → голосование по подвопросам → итог «известно / спорно / неизвестно» со ссылками | исследования: рынки, технологии, факты с цифрами |

### Режим «Исследование»

Совет написал для себя ТЗ (`docs/research-tz/`), и режим сделан по нему. Отличия от «Дебатов»:

- **Постановка.** Председатель задаёт рамки (период, география, единицы) и 3–5 подвопросов. Каждому автору
  достаётся свой угол зрения: рынок и первичные данные, технология, экономика, скептик.
- **Варианты пишутся вслепую и без поиска.** Каждый факт помечается: `[DOC]` — из ваших файлов, `[CALC]` —
  расчёт, `[MEM]` — «из памяти модели». Ключевые утверждения выносятся отдельным списком, их номера (A-C1, B-C2…)
  проставляет программа.
- **Критика** отмечает спорные утверждения и пропущенные подвопросы.
- **Арбитраж доказательств** (вместо проверки фактов лидеров). Модель с поиском (по умолчанию Perplexity из
  «Проверки фактов») проверяет до 10 важных утверждений всех вариантов. Проверка идёт двумя заданиями:
  найти подтверждения и найти опровержения. Получается реестр источников E1, E2… Ссылка, которой нет среди
  результатов поиска, подтверждением не считается.
- **Доработка** идёт по реестру и выжимкам чужих вариантов, а не по их полным текстам, — так варианты не сливаются
  в один.
- **Голосование** выбирает лучший вариант по каждому подвопросу — это каркас раздела итога, а не проверка истины.
- **Итог:**
  - синтез по подвопросам;
  - **«известно»** — только подтверждённое источниками или вашими документами, иначе председателю возвращают
    ответ;
  - «спорно» — с позициями и причиной расхождения;
  - «неизвестно» — с тем, как узнать;
  - «что изменило бы выводы» и «что исследовать дальше».

  В отчётах есть разделы «Источники» и «Проверка утверждений».

**Цена** примерно как у «Дебатов» с проверкой фактов: столько же вызовов, только поиск перенесён из конца в середину.
Перед первым исследованием нажмите «Настройки → Факты и голос → Проверить поиск» (один запрос, обычно меньше
цента): кнопка покажет, работает ли поиск и возвращает ли он ссылки.

**Пилот.** Каждую часть можно выключить в «Настройки → Факты и голос → Режим «Исследование»» (или в
`config.yaml`, раздел `research`), чтобы сравнить, что помогает. Набор вопросов и метрики для сравнения — в итоге
заседания-ТЗ (раздел 7): возьмите 2 вопроса, проведите их в «Дебатах» и в «Исследовании» и сравните, сколько ссылок
реально подтверждают утверждения и сколько ошибок осталось в итоге.

## Установка

```bash
cd ai-council
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env    # и вставьте ключ с https://openrouter.ai/keys
```

Ключ нужен один: `OPENROUTER_API_KEY`. На счёт OpenRouter надо положить немного денег.
Одно заседание из 5 моделей в режиме `debate` обычно стоит от нескольких центов до ~$0.5,
в зависимости от моделей и длины ответов.

## Веб-интерфейс

```bash
python -m council web          # затем откройте http://127.0.0.1:8000
```

Интерфейс рассчитан и на компьютер, и на телефон: на компьютере разделы — в меню слева, на телефоне — в нижней панели
(«Новый · Архив · Статистика · Настройки»). Светлая и тёмная тема включаются по настройке системы.
Что изменилось в последней переработке и почему — в [docs/redesign.md](docs/redesign.md).

**Новый вопрос**
- Напишите вопрос, при желании приложите файлы («Файлы», перетаскивание на поле или вставка скриншота Ctrl+V) или
  надиктуйте («Голосом»; работает по HTTPS и на localhost — запись расшифровывает `transcribe_model` из config.yaml).
- Выберите, как обсуждать: «Подробное обсуждение», «Быстрый ответ» или «Выбрать из моих вариантов».
- Остальное — в свёрнутых «Параметрах»: участники, председатель, адвокат дьявола, раунды, критерии, контекст,
  компактные варианты, проверка фактов, демо-режим, лимит стоимости. Строка под заголовком показывает, что выбрано.
- Стоимость считается сама, пока вы пишете («Оценка: $0.31 – $0.78 · баланса хватит»; нажмите — подробности).
  Перед стартом окно подтверждения покажет оценку ещё раз.

**Заседание**
- Пока идёт: «Этап 3 из 6: Критика», полоса прогресса, список этапов и по каждой модели — «думает», «пишет ответ»,
  «повтор» с причиной, «готово» и секундомер. Если «думающая» модель рассуждает долго, появится пояснение.
  Кнопка «Остановить».
- После: сначала **решение** — с пометками «Мнения совета совпадают / разошлись», «Ничья за первое место»,
  «Председатель выбрал не лидера», ответ целиком и кнопки «Уточнить», «Повторить», «Скачать»
  (полный отчёт, итог с обоснованием или только решение — в PDF, Word, Markdown или в браузере).
- Ниже: «Почему так, риски и особые мнения», голосование простыми словами (таблица Шульце/Борда, бюллетени и
  методика — в «Как считали»), все варианты (каждый открывается целиком: итоговая версия, до критики, оценки, голоса),
  таблица критики (нажмите на оценку — откроется отзыв), журнал событий со ссылкой «Скачать журнал для разбора ошибок».
- Когда вкладка в фоне, по окончании придёт уведомление со звуком; ход виден и в заголовке вкладки.

**Архив, статистика, настройки**
- «Архив» — все заседания с поиском и фильтром, меню «Скачать» у каждого, удаление.
- «Статистика» — расходы по месяцам, средняя цена и время, какие модели чаще побеждают и сбоят, как часто председатель
  выбирает не лидера.
- «Настройки» — всё без терминала:
  - модели: включить/выключить, заменить (подсказки из каталога OpenRouter с датой и ценой), добавить, удалить,
    «Проверить, есть ли модели новее»;
  - параметры заседания по умолчанию, экономия, проверка фактов, модель для голосовых;
  - оформление отчётов;
  - «Программа»: версия, проверка обновлений, **обновление и перезапуск кнопкой**, журналы программы, резервные копии настроек.

  Настройки сохраняются в `config.yaml` с комментариями; неверные значения не сохраняются.

**Журналы для разбора ошибок.** У каждого заседания — «Скачать журнал для разбора ошибок» (zip: события по моделям,
стенограмма с сырыми ответами, журнал программы, версия и настройки); в «Настройки → Программа» — журналы программы и
прерванные заседания; в Telegram — `/logs`. Ключи и токены в журналах скрываются, вопросы и ответы моделей — внутри.
На сервере они лежат в томе с отчётами: `runs/logs/*.log`, `runs/<id>.events.jsonl`, `runs/failed/<id>.json`.

Для кнопок «Обновить» и «Перезапустить» на сервере один раз включается служба
(`sudo bash /opt/ai-council/ai-council/deploy/web-control.sh install`, при новой установке — автоматически):
веб-интерфейс только оставляет заявку, а выполняет её служба на сервере — контейнеру не нужен доступ к Docker.

Без ключа доступен демо-режим. Сервер по умолчанию слушает только `127.0.0.1`. Чтобы открыть его в сеть,
задайте пароль (`WEB_PASSWORD`, логин — `WEB_USER`) и используйте HTTPS — на сервере это делает install.sh
(Caddy + Let's Encrypt). Без пароля не открывайте интерфейс наружу: любой сможет тратить ваш баланс.

## Telegram-бот

1. Создайте бота: напишите [@BotFather](https://t.me/BotFather) команду `/newbot` и получите токен.
2. Добавьте в `.env`:
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC...
   TELEGRAM_ALLOWED_USERS=          # пока пусто
   ```
3. Запустите `python -m council telegram` и напишите боту. Он ответит «доступ закрыт» и покажет ваш Telegram ID.
   Впишите ID в `TELEGRAM_ALLOWED_USERS` (несколько через запятую) и перезапустите бота.

Белый список обязателен: каждое заседание тратит баланс OpenRouter, поэтому посторонним бот отвечает только их ID.

Длина вопроса не ограничена. Telegram не пропускает сообщения длиннее 4096 символов и сам режет длинный текст на части;
бот склеивает такие части в один вопрос (если предыдущая часть была почти предельной длины и следующая пришла в течение
15 секунд). Очень длинный текст удобнее приложить файлом (.txt, .docx, .pdf) с короткой подписью-вопросом.

Как пользоваться:
- **Напишите вопрос** (или пришлите голосовое). Бот пришлёт карточку: режим, сколько моделей, кто председатель,
  примерная стоимость и баланс. Кнопки: «▶️ Начать», «⚙️ Настроить» (режим, раунды, участники, проверка фактов,
  компактные варианты, демо — переключатели ✅/▫️), «✖️ Отмена».
- **Во время заседания** одно сообщение обновляется на ходу: полоса этапов «▰▰▱▱▱▱ Этап 3 из 6: Критика», что
  происходит на этапе, строка на каждую модель, стоимость и время. Кнопка «⏹ Остановить».
- **Решение** приходит коротко — заголовок, кто предложил и сколько голосов за первое место, 3–5 строк сути и
  «🟢 Мнения совета совпадают» (или «разошлись»). Кнопки: «📖 Полный ответ», «📊 Голоса», «📄 Отчёт PDF»,
  «📎 Другие форматы» (полный отчёт, итог с обоснованием или только решение — PDF, Word, Markdown),
  «💬 Уточнить» (следующее сообщение станет уточняющим вопросом), «🔁 Повторить».
- **Файлы:** пришлите фото, скриншот или документ (PDF, Word, Excel, текст) — с подписью-вопросом или
  перед вопросом (несколько файлов и альбомы тоже можно). `/clear` — убрать приложенные файлы.
- `/settings` — настройки чата с кнопками (те же, что в «⚙️ Настроить»).
- `/archive` — прошлые заседания: кнопки с названиями, листание; нажмите — придёт решение с кнопками отчётов.
  Поиск: `/archive кофейня`.
- `/evaluate`: выбор из готовых вариантов. Первая строка — вопрос, дальше по варианту на строку:
  ```
  /evaluate Какую БД выбрать для аналитики?
  PostgreSQL
  ClickHouse
  BigQuery
  ```
- `/budget 0.5` — лимит одного заседания, `/stats` — статистика, `/stop`, `/cancel`, `/logs`, `/help`.
- **В группах** бот реагирует только на команды (`/ask вопрос`, `/evaluate …`).

Настройки (режим, раунды, участники, лимит, демо) запоминаются для каждого чата. Заседания из бота
сохраняются в `runs/`, поэтому видны и в истории веб-интерфейса.

## Сервер и Docker

Чтобы бот работал круглосуточно, без включённого компьютера, запустите его на сервере в Docker:

```bash
docker compose up -d                   # Telegram-бот
docker compose --profile https up -d   # + веб-интерфейс из интернета по HTTPS с паролем (DOMAIN, WEB_PASSWORD в .env)
docker compose --profile web up -d     # или веб-интерфейс только через SSH-туннель
```

Установка на чистый сервер Ubuntu одной командой. Скрипт спросит всё нужное (ключи, участников, лимит,
доступ, адрес и пароль сайта), для каждого пункта покажет, где его взять, и всё проверит:

```bash
curl -fsSL https://raw.githubusercontent.com/avict-boop/Start-and-end/refs/heads/claude/multi-ai-comparison-tool-50nc5z/ai-council/install.sh | sudo bash
```

Подробная инструкция с нуля, от аренды сервера до первого вопроса: **[DEPLOY.md](DEPLOY.md)**.

## Маленький сервер (1 ГБ памяти)

Вёрстка длинного PDF-отчёта занимает около 300 МБ памяти. Чтобы сервер с 1 ГБ не «замирал»:

- отчёты верстаются в отдельном процессе и по одному на весь сервер (сайт, бот и пересборка архива — по очереди);
- при установке и при обновлении программа сама включает файл подкачки на 2 ГБ, если памяти меньше 2 ГБ и
  подкачки нет (нужно свободных больше 4 ГБ на диске; на некоторых VPS подкачку включать запрещено).

Проверить: `free -h` — в строке `Swap` должно быть около 2 ГБ.

## Как выкатить обновление интерфейса на сервер

Новый интерфейс лежит в ветке `claude/ui-redesign`. Сервер, установленный через `install.sh`, обновляется из ветки
`claude/multi-ai-comparison-tool-50nc5z`. Ваши `config.yaml`, `.env`, архив и отчёты при обновлении не трогаются.

**Способ 1 — обычный (рекомендую).** Сначала перенесите изменения в рабочую ветку, потом обновите сервер кнопкой.

1. На GitHub откройте репозиторий → **Pull requests → New pull request**.
2. Выберите: base — `claude/multi-ai-comparison-tool-50nc5z`, compare — `claude/ui-redesign` → **Create pull request**.
3. Нажмите **Merge pull request → Confirm merge**.
4. Откройте сайт совета → **Настройки → Программа** → «Проверить обновления» → **«Обновить программу»**.
   Подождите 1–5 минут: страница перезагрузится сама. (Без браузера — на сервере `sudo ai-council update`.)
5. Откройте сайт на телефоне. Если видите старый вид — обновите страницу (потяните вниз). Новые файлы подхватываются
   сами, отдельно чистить кэш не нужно.
6. В Telegram напишите боту любой вопрос — должна прийти карточка с кнопками «▶️ Начать / ⚙️ Настроить / ✖️ Отмена».

**Способ 2 — попробовать на сервере до слияния.** Сервер начнёт обновляться из новой ветки.

```bash
cd /opt/ai-council
sudo git fetch origin claude/ui-redesign
sudo git checkout claude/ui-redesign      # config.yaml в этой ветке не менялся — ваши настройки останутся
sudo ai-council update                     # пересоберёт и перезапустит бота и сайт
```

Вернуться к прежней версии:

```bash
cd /opt/ai-council
sudo git checkout claude/multi-ai-comparison-tool-50nc5z
sudo ai-council update
```

Если что-то пошло не так: `sudo ai-council logs` покажет журнал, а «Настройки → Программа → Журнал» — ход обновления.

## Командная строка

```bash
# Пробный прогон без ключа и без затрат (фейковые ответы):
python -m council ask "Какой стек выбрать для MVP интернет-магазина?" --mock

# Проверить модели и оценить стоимость, ничего не запуская (ключ не нужен)
python -m council ask "Какой стек выбрать для MVP интернет-магазина?" --dry-run

# Полноценное заседание (перед стартом покажет план и стоимость и спросит подтверждение; -y — без вопроса)
python -m council ask "Какой стек выбрать для MVP интернет-магазина?"

# Быстрый режим, свои критерии, лимит бюджета
python -m council ask "Как назвать кофейню у университета?" --mode quick --criteria "запоминаемость,уникальность,звучание" --budget 0.3

# Два раунда дебатов, контекст из файла
python -m council ask "Стоит ли переводить сервис на микросервисы?" --rounds 2 --context-file context.md

# Выбор из готовых вариантов (в файле варианты разделены строкой ---)
python -m council ask "Какую БД выбрать для аналитики?" --option "PostgreSQL" --option "ClickHouse" --option "BigQuery"
python -m council ask "Какой бизнес-план лучше?" --options-file plans.txt

# С файлами: картинки, PDF, Word, Excel, текст (до 10 файлов, каждый до 20 МБ)
python -m council ask "Какой квартал был лучшим? Учти бриф." --file график.png --file бриф.docx

# Только часть участников
python -m council ask "..." --only claude,gemini,deepseek

# Уточняющий вопрос к заседанию из архива (ключ — в первой колонке `archive`)
python -m council ask "А если бюджет вдвое меньше?" --followup 757240384f

# Статистика: расходы, длительность, успехи моделей
python -m council stats

# Найти точные id моделей на OpenRouter
python -m council models kimi
```

Результаты сохраняются в `runs/` — это и есть архив заседаний:
- `*.pdf` — отчёт для чтения и печати: решение, голосование, все варианты с форматированием, критика, расходы;
- `*.docx` — тот же отчёт для Word / Google Docs (можно править);
- `*.md` — тот же отчёт в Markdown;
- `*.summary.pdf`, `*.summary.docx`, `*.summary.md` — **только итог**: запрос и итоговое решение
  (ответ, почему, особые мнения, риски) без вариантов, критики и голосования — обычно одна страница;
- `*.decision.pdf`, `*.decision.docx`, `*.decision.md` — **только решение совета**: итоговый ответ без вопроса,
  обоснования, рисков, вариантов и голосования — удобно переслать как готовый документ;
- `*.json` — полная стенограмма, включая сырые ответы каждой модели. Отчёты строятся из неё,
  поэтому после обновления программы отчёты старых заседаний досоздаются автоматически
  (вручную: `python -m council reports`, пересобрать всё: `--force`).

Архив в консоли: `python -m council archive [поиск]`.

## Отчёты: оглавление и своё оформление

Отчёт начинается с решения, а полный запрос стоит в конце. Подробно о том, что и зачем изменено, — в
[docs/reports.md](docs/reports.md), примеры — в [docs/examples/](docs/examples/). В полном отчёте есть оглавление:
в PDF — с номерами страниц и закладками для навигации, в Word — поле оглавления со ссылками на разделы (номера
страниц в нём появятся после F9). Логотип, название компании, фирменный цвет и текст
колонтитула задаются в `config.yaml`:

```yaml
branding:
  title: "ООО «Ромашка»"
  logo: branding/logo.png      # положите файл в папку branding рядом с config.yaml
  color: "#0a7d5a"
  footer: "Конфиденциально"
```

Новые отчёты сразу выходят в фирменном виде; уже сохранённые пересоберите: `python -m council reports --force`
(на сервере: `ai-council reports --force`).

## Как выкатить новые отчёты

Новые отчёты лежат в ветке `claude/reports-redesign`. Выкатываются так же, как обновление интерфейса (см. выше):

1. На GitHub: **Pull requests → New pull request**, base — `claude/multi-ai-comparison-tool-50nc5z`, compare —
   `claude/reports-redesign` → **Create pull request → Merge pull request → Confirm merge**.
2. На сайте совета: **Настройки → Программа → «Обновить программу»** (или на сервере `sudo ai-council update`).
   Образ пересоберётся вместе с новыми шрифтами (Inter, JetBrains Mono) — это займёт на пару минут дольше обычного.
3. Старые отчёты пересоберутся сами в фоне после запуска: номер версии отчётов поднят, программа это заметит.
   Чтобы не ждать — **Настройки → Отчёты → «Пересобрать отчёты архива»** или `sudo ai-council reports --force`.
   Данные заседаний не меняются, перестраиваются только файлы PDF, Word и Markdown.

Попробовать до слияния и вернуться обратно — как в «Способе 2» выше, только с веткой `claude/reports-redesign`.
После возврата на старую ветку выполните `sudo ai-council reports --force`, чтобы отчёты снова стали прежними.

## Если заседание прервалось: пауза и продолжение

Заседание не пропадает, если кончился бюджет или деньги на OpenRouter, случился сбой, его остановили вручную или
сервер перезапустился (например, при обновлении программы). Оно встаёт на паузу, а все уже полученные ответы
моделей сохраняются. При продолжении они берутся из сохранённого бесплатно, платные запросы идут только туда,
где ответа ещё нет.

- **На сайте:** у такого заседания карточка «Заседание на паузе» с причиной и потраченной суммой — укажите бюджет
  и нажмите «Продолжить» (или «Удалить»). На стартовом экране есть напоминание о приостановленных заседаниях, в
  списке они помечены «на паузе» или «прервано — можно продолжить».
- **В Telegram:** бот присылает сообщение с кнопками «▶️ Продолжить», «💰 +$1 / +$3 / +$5 и продолжить», «🗑 Удалить».
  После перезапуска сервера бот сам сообщает о прерванных заседаниях. Список — командой `/paused`.
- **Бюджет на ходу:** когда потрачено 80% бюджета, сайт и бот предупреждают и предлагают поднять его — заседание
  продолжится без остановки. На сайте поднять бюджет можно и в любой момент — ссылкой «поднять бюджет» рядом со
  стоимостью.
- **Кончились деньги на OpenRouter:** пополните баланс на openrouter.ai/settings/credits и нажмите «Продолжить».
- **Исчерпан лимит расходов API-ключа** (OpenRouter: «Key limit exceeded», например недельный лимит $50): поднимите
  или снимите лимит ключа на openrouter.ai/settings/keys (или дождитесь сброса) и нажмите «Продолжить». Неверный
  или отключённый ключ тоже ставит заседание на паузу.
- **Заседание уже в архиве, но со сбоями** (например, проведено до этого обновления, когда лимит ключа «выбивал»
  участников по одному): на его странице в блоке «Сбои» есть кнопка «Доделать заседание». Оплаченные ответы
  берутся из стенограммы, заново спрашиваются только шаги со сбоями и то, что от них зависит; новый итог
  заменяет старый.

Сохранённое лежит в `runs/paused/` (в Docker — в томе с архивом, переживает обновления) и удаляется, когда
заседание завершено.

## Вложения: как модели их видят

- **Документы** (PDF, Word, Excel, TXT/MD/CSV/JSON): из них извлекается текст и добавляется к запросу
  (до 60 000 символов на документ и 150 000 на все вместе; больше — обрезается с предупреждением).
  PDF-сканы без текстового слоя прикладывайте картинками.
- **Картинки** уменьшаются до 1600 px по длинной стороне и передаются моделям, которые умеют смотреть
  на изображения (это берётся из каталога OpenRouter). Для остальных одна из «зрячих» моделей
  (по возможности председатель) заранее подробно описывает картинки текстом — это видно отдельным этапом
  «Описание изображений», а само описание — в отчёте и по кнопке «Описание картинок».
- Вложения получают этапы постановки, предложений, критики, доработки и вердикта (голосованию они не нужны).
  Это увеличивает стоимость — оценка перед запуском её учитывает.
- Файлы хранятся в архиве рядом с заседанием (`runs/<id>.files/`), попадают в отчёты (список, картинки)
  и удаляются вместе с заседанием.

## Настройка участников

Участники задаются в файле `config.yaml`. Чтобы подключить дополнительную модель, включите её (`enabled: true`) или добавьте свою:

```yaml
members:
  - name: grok
    model: x-ai/grok-4
    enabled: true
    temperature: 0.9   # необязательно: свои параметры для участника
```

Уже подготовлены, но выключены: **Grok** (xAI), **Qwen** (Alibaba), **Mistral**, **Llama** (Meta),
**Perplexity Sonar** (с поиском в интернете, подходит как фактчекер).

### «Подобрать состав» под вопрос

Справа от вопроса есть кнопка **«Предложить состав для этой задачи»**. Модель-советник разбирает вопрос и подбирает
модели, роли и поиск под выбранный вами режим (режим он не меняет) — по каталогу OpenRouter, обзорам моделей, найденным в интернете (запоминаются на 3 недели),
и вашей истории; у каждой причины видно, на чём она основана. «Применить» ставит этот состав только для текущего
вопроса — настройки не меняются. Там же, в «Параметрах», можно включить **поиск в интернете** отдельным участникам
(🌐): для свежих цен, рынков и новостей. Подробно — `docs/logic.md`, раздел 11а.

### Что изменено по аудиту совета

Совет проверил всё приложение (ТЗ — `docs/audit-tz/`) и дал рекомендации; они внедрены, все пределы вынесены в
`config.yaml` и «Настройки» со значениями, которые предложил совет. Главное: исследование проверяет 20 утверждений
(дубли объединяются, непубличное сразу идёт в «неизвестно», «не удалось проверить» ищется второй раз, новые
утверждения после доработки тоже проверяются), голосующие видят реестр источников, итог начинается с карточки
решения, «известно» привязано к проверенным утверждениям; «Быстрый ответ» не теряет идей, «Выбор из вариантов»
умеет сказать «ни один не подходит»; «Куда ушли деньги» по этапам; резерв бюджета и остаток лимита ключа.
Подробно — `docs/logic.md`, раздел 4б.

### Пилот: окупается ли исследование

Под решением каждого заседания можно поставить оценку пользы (★ 1–5). В «Статистике → Пилот: исследования» —
по каждому исследованию: сколько утверждений подтверждено источниками, живые ссылки (программа сама открывает
каждую ссылку реестра — мёртвые ничего не подтверждают), раскрытые подвопросы, цена, сбои и ваша оценка; ниже —
тот же вопрос в разных режимах рядом. Тот же вопрос в другом режиме — кнопка «Повторить».

### Как перейти на более новые модели

Разработчики выпускают новые модели несколько раз в год, а id в `config.yaml` сами не обновляются.
Чтобы узнать, чем обновить совет:

```bash
ai-council models --upgrades          # на сервере; локально: python -m council models --upgrades
```

Для каждого участника команда покажет его текущую модель с датой выхода и более новые модели —
того же семейства (например, Sonnet → новый Sonnet) и самые свежие у того же разработчика, с ценой,
длиной контекста и пометками 🖼 (видит картинки) и 🎤 (понимает звук). Если модели больше нет
на OpenRouter, это тоже будет видно.

Свежие модели вообще: `ai-council models` (сначала новые), по разработчику: `ai-council models claude`.
Замена — поменять `model:` у участника (`ai-council config`), изменения подхватятся со следующего заседания.
Перед запуском программа сама проверяет, что все id существуют, и подсказывает похожие.
Совет: меняйте модели по одной и сравнивайте результат кнопкой «Повторить» на знакомых вопросах.

## Структура

```
council/
  client.py    клиент OpenRouter: ретраи, таймауты, учёт стоимости
  config.py    конфиг (YAML) и .env
  schemas.py   pydantic-схемы ответов на каждом этапе
  prompts.py   промпты для ролей и этапов
  voting.py    разбор JSON, анонимизация, проверка ответов, подсчёт Борда
  session.py   оркестратор заседания (этапы 0–6, кворум, бюджет)
  report.py    отчёт Markdown и стенограмма JSON
  estimate.py  проверка моделей и оценка стоимости до запуска
  mock.py      фейковый клиент для --mock и тестов
  cli.py       командная строка
  web/         веб-интерфейс: FastAPI + SSE (app.py) и страница без сборки (static/)
  telegram/    Telegram-бот: клиент Bot API (api.py), логика бота (bot.py), разметка (format.py)
tests/         pytest
```

Тесты: `pip install pytest && python -m pytest`.
