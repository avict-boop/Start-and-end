# Анализатор БАД

Программа проверяет, соответствует ли состав и маркировка биологически активной добавки (БАД) требованиям законодательства РФ и ЕАЭС. Этикетку можно сфотографировать телефоном — она распознаётся на русском, английском, немецком, французском, испанском, итальянском и китайском языках.

> ⚠️ Результат носит справочный характер и **не заменяет** экспертизу и государственную регистрацию (СГР).
> Справочники в `bad_checker/data/` — **стартовый набор**. Перед практическим применением их нужно сверить с официальными текстами нормативных актов.

## Что проверяется

| Проверка | Нормативная база | Справочник |
|---|---|---|
| Запрещённые растения, вещества, гормоны, лекарственные субстанции | ТР ТС 021/2011, Приложение 7; 3-ФЗ; ПП РФ № 964 | `data/prohibited.json` |
| Суточная доза не выше верхнего допустимого уровня (ВДУ), **во сколько раз превышена норма**, доля от адекватного уровня (АУП) | Единые сан.-эпид. требования (Решение Комиссии ТС № 299), гл. II, разд. 1, прил. 5 | `data/nutrients.json` |
| Неразрешённые пищевые добавки (E-коды) | ТР ТС 029/2012 | `data/additives.json` |
| Обязательные элементы маркировки, маркировка на русском языке | ТР ТС 022/2011, ст. 4.1, 4.4, 4.8 | `data/rules.json` |
| Заявления о лечебных свойствах (в т.ч. на иностранных языках) | ТР ТС 022/2011; 38-ФЗ «О рекламе», ст. 25 | `data/rules.json` |
| Номер СГР: формат, дата выдачи, код вида продукции | ТР ТС 021/2011, ст. 24 | `sgr.py` |

Что ещё умеет программа:
- переводит единицы: г, мг, мкг, МЕ / IU / UI, а также 毫克 и 微克;
- понимает иностранную запись чисел: «5,000 IU», «1 000 mg»;
- пересчитывает дозу на сутки: количество на 1 приём × число приёмов в день;
- предупреждает, если для минерала указана масса соли («магния цитрат», «Magnesiumcitrat»), а не элемента; понимает американское соглашение «Zinc (as zinc picolinate) 30 mg».

## Устройство

```
bad_checker/data/   справочники (JSON) — единственный источник данных для обеих версий
site/               сайт для телефона и компьютера: проверка и распознавание фото прямо в браузере
  js/engine.js      движок проверки на JavaScript (результаты совпадают с Python-версией — это проверяется тестом)
bad_checker/        Python-движок, командная строка, веб-сервер с API
tools/build_site.py сборка статического сайта для публикации
```

Сайт работает без сервера. Фото распознаются на устройстве пользователя (Tesseract.js) и никуда не отправляются. Языковые данные загружаются при первом распознавании и затем кэшируются.

## Сайт на GitHub Pages (временный адрес)

Однократная настройка:
1. Влейте изменения в ветку `main`.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.

После этого каждое изменение в `main` прогоняет тесты и публикует сайт (`.github/workflows/pages.yml`). Адрес будет такой: `https://<владелец>.github.io/<репозиторий>/`.

На телефоне откройте адрес и добавьте страницу на главный экран: в Safari — «Поделиться → На экран «Домой»», в Chrome — «Добавить на главный экран». Сайт откроется как приложение и будет работать без сети (кроме первой загрузки языков распознавания).

## Свой сервер и домен

Тот же сайт отдаёт Python-сервер, который дополнительно предоставляет API и серверное распознавание фото:

```bash
docker build -t bad-checker .
```

```bash
docker run -d -p 8000:8000 --restart unless-stopped --name bad-checker bad-checker
```

Перед контейнером поставьте nginx или Caddy с HTTPS-сертификатом для вашего домена. HTTPS обязателен: без него не работают установка на главный экран и офлайн-режим. Пример для Caddy (сертификат получается автоматически):

```
bad.example.ru {
    reverse_proxy 127.0.0.1:8000
}
```

Можно обойтись и без Docker — просто выложить на любой статический хостинг содержимое папки, которую собирает `python tools/build_site.py`.

## Запуск на компьютере

Нужен Python 3.10 или новее. Ядро и веб-сервер работают без сторонних библиотек.

```bash
python -m bad_checker.web
```

Откройте http://127.0.0.1:8000. Чтобы открыть сайт с телефона в той же Wi-Fi-сети, запустите сервер с `--host 0.0.0.0` и откройте `http://<IP компьютера>:8000`.

### Командная строка

```bash
python -m bad_checker examples/multivitamin_ok.json
```

```bash
python -m bad_checker examples/us_label.txt
```

```bash
python -m bad_checker examples/label_photo.png --format md -o report.md
```

Опции: `--per-day N` — число приёмов в сутки; `--format text|md|json` — формат отчёта. Коды возврата: `0` — соответствует, `1` — есть предупреждения, `2` — есть нарушения.

Для распознавания фото в командной строке и на сервере нужен Tesseract:

```bash
sudo apt-get install -y tesseract-ocr tesseract-ocr-rus tesseract-ocr-deu tesseract-ocr-fra
```

```bash
pip install -r requirements.txt
```

### API

`POST /api/analyze` принимает JSON с полями `name`, `composition_text`, `label_text`, `units_per_day`, `amounts_per_unit` и `image` (data URL фото). В ответе — вердикт, замечания и дозы с полями `ratio_upper` («во сколько раз превышен ВДУ») и `ratio_adequate`. Проверить, доступно ли распознавание: `GET /api/health`.

## Входные данные

Текст или фото: если есть заголовок «Состав:», «Ingredients», «Supplement Facts», «Zutaten», «配料» и т. п., компонентами считаются строки после него — до рекомендаций, противопоказаний, срока годности и т. п. Без заголовка компонентом считается каждая строка (или часть через `;`).

JSON:

```json
{
  "name": "Название продукта",
  "daily_dose": {"units_per_day": 2, "unit_name": "капсула", "amounts_per_unit": true},
  "ingredients": [
    {"name": "Витамин D3 (холекальциферол)", "amount": 1000, "unit": "МЕ"},
    "Магний (в пересчете на магний) 100 мг"
  ],
  "label_text": "Полный текст этикетки…"
}
```

## Проверка СГР

Программа находит номер свидетельства о госрегистрации (например, `RU.77.99.11.003.R.001234.05.24`). Она проверяет формат, месяц и год выдачи, а также код вида продукции (для БАД — `11`). Действует ли свидетельство, нужно проверять вручную в Едином реестре ЕАЭС (portal.eaeunion.org): стабильного публичного API у реестра нет.

## Как дополнить базу

Справочники — обычные JSON-файлы; код менять не нужно. Изменения сразу подхватывают и сайт, и Python-версия. Например, запрещённое растение в `data/prohibited.json`:

```json
{"id": "...", "names": ["русское название"], "latin": ["Genus species", "english name"],
 "category": "растение", "basis": "ТР ТС 021/2011, прил. 7", "note": "..."}
```

`names` — русские названия (учитываются падежные окончания), `latin` — названия латиницей и на других языках (ищутся как целые слова). Поле `"severity": "warning"` помечает ограниченный компонент: продукт с ним получает статус «требует проверки», а не «нарушение».

## Тесты

```bash
python -m pytest -q
```

Тесты покрывают оба движка и проверяют, что JavaScript-версия на контрольных этикетках (русских, английских, немецких, французских, китайских) даёт те же результаты, что и Python-версия.
