# Start-and-end

## dosrip — восстановление старых DOS-игр

Загружаете zip со всеми файлами игры, получаете папку (или zip) с извлечённой графикой, звуком,
музыкой, распакованным и дизассемблированным кодом и HTML-отчётом.

### Приложение для macOS (Apple Silicon)

Готовый `dosrip-<версия>-arm64.dmg` собирается автоматически в GitHub Actions на Mac с M-процессором
(вкладка **Actions** → «macOS app (Apple Silicon)» → артефакт `dosrip-macos-arm64`; для тегов `v*` — в Releases).

1. Откройте `.dmg` и перетащите **dosrip** в «Программы».
2. Приложение подписано ad-hoc, без сертификата Apple Developer, поэтому при первом запуске macOS его заблокирует.
   Откройте «Системные настройки → Конфиденциальность и безопасность» и нажмите «Всё равно открыть».
   Можно и через терминал: `xattr -dr com.apple.quarantine /Applications/dosrip.app`.
3. Перетащите zip с игрой в окно. Результаты сохраняются в `~/Documents/dosrip/`, кнопка «Показать в Finder» открывает папку.

Собрать вручную на Mac с Apple Silicon: `pip install -e ".[mac]" pyinstaller && ./packaging/macos/build.sh`.

### Установка (Python, любая ОС)

```bash
pip install -e ".[web]"
```

### Запуск

Через браузер: откройте http://127.0.0.1:8000, загрузите zip, получите отчёт и кнопку «Скачать всё одним zip».

```bash
dosrip serve
```

Из командной строки:

```bash
dosrip run game.zip -o game_restored --zip-result
```

### Что получается

| Папка | Что внутри |
|---|---|
| `graphics/` | PNG из PCX, BMP, GIF, LBM/ILBM (Deluxe Paint), сырых экранов VGA 320×200; `palettes/` — палитры VGA |
| `animations/` | FLI/FLC (Autodesk Animator) → анимированный GIF |
| `sound/` | Creative VOC → WAV, WAV |
| `music/` | MIDI; XMIDI (Miles Sound System) → MIDI; CMF → MIDI; MOD, S3M |
| `code/<файл>/` | `listing.asm` — дизассемблированный код с метками функций и комментариями к вызовам DOS/BIOS, `callgraph.txt`, `strings.txt`, `info.json` (компилятор, упаковщик, расширитель), `unpacked.exe` |
| `text/` | тексты в CP437, перекодированные в UTF-8 |
| `original/` | исходные файлы |
| `report.html` | всё вместе: галерея, проигрыватель звука, ссылки на код, список нераспознанного |

Ресурсы ищутся по сигнатурам **внутри любых файлов**, поэтому находятся и в архивах игры (`.DAT`, `.RES`, `.LIB`),
и внутри самих EXE.

### Как восстанавливается код

1. **Распаковка.** Многие игры сжаты упаковщиками (LZEXE, PKLITE, EXEPACK, DIET и др.). dosrip не пишет
   распаковщик под каждый из них: он запускает встроенный в EXE распаковщик в эмуляторе процессора 8086 (Unicorn),
   ловит переход в распакованный код и снимает дамп. Таблица релокаций восстанавливается двойным запуском
   с разных адресов. Результат — обычный рабочий `unpacked.exe`.
2. **Дизассемблирование.** Рекурсивный обход кода от точки входа по переходам и вызовам (Capstone):
   функции, метки, отмеченные сегментные ссылки, комментарии к `int 21h`/`int 10h`.
3. **Определение компилятора и DOS-расширителя** (Turbo Pascal, Borland C++, Microsoft C, Watcom, DOS/4GW...).

### Честные ограничения

- **Исходный код в первоначальном виде вернуть нельзя никакой программой**: имена переменных, функций
  и комментарии при компиляции теряются. Получается ассемблер с размеченной структурой. Для перевода в
  псевдо-C откройте `unpacked.exe` в Ghidra.
- 32-битные игры на DOS/4GW (формат LE) только определяются, их код нужно смотреть в Ghidra/IDA.
- Собственные форматы сжатия конкретных игр (например, спрайты без заголовков, уровни) автоматически не
  распознаются. Такие файлы попадают в раздел «Не распознано» с оценкой энтропии; под них пишется плагин.
- Распаковщик проверен на тестовом упаковщике (`tests/asm/stub.asm`). На реальных LZEXE/PKLITE-файлах он
  ещё не проверялся.
